## 現價用哪個來源

`auction_brief.py`、`auction_changes.py --live`、`leveling_route.py --live`／`--me` 每次比較兩個來源的時間，自動用較新的：

- **官方 API**：腳本直接取一次，時間是回應的 `Last-Modified`，每小時更新（2026-11-25 約 :26）。
- **完整掃描**：同一輪的 `Auctionator.lua` 與 `DungeonsForeverProf.lua`，時間是掃描開始，有各價位件數。要先 `/reload` 或登出才寫進存檔。

網站每小時紀錄（`auction-data` 分支）和 Cloudflare Worker 的 `market-depth.json` 都是 API 的副本，最多一樣新，不必另外比。行情頁不會自動讀到本機掃描，要重建 `market/data.json` 才會更新。

輸出會寫「現價用拍賣小幫手掃描 11/25 11:59，比 API 11/25 11:26 新」，回答時照寫來源與時間（JSON 在 `priceSource`）。`--source api` 或 `--source scan` 可強制來源，遊戲裝在別處時加 `--root`。掃描裡沒有的物品當作沒貨；掃描讀不出的列沿用 API。API 失敗時只接受三小時內的掃描。`faction_spread.py` 固定用 API，因為跨陣營頁標示的是官方時間。

## 阿莫比分陣營價

依名稱查指定物品，或讀個人頁上所有可複製的名稱時，執行下列指令。

```sh
python3 '<skill-dir>/scripts/amobi_item_prices.py' '配方：貓鼬藥劑'
python3 '<skill-dir>/scripts/amobi_item_prices.py' --from-html speculation/index.html alchemy/index.html endgame/index.html
```

每項列出全服最低價、件數、日期與各拍賣場最近看到的最低價和時間；同名物品會標出品質與類型。快取預設 1 小時。

### 現金與遊戲金幣比值

查當天第三方公開報價時，優先打開直接顯示《魔獸世界：永恆》、台服、PvP、部落和幣別的明細。核對單價是每 G 或每包、最低數量與已知費用，標明報價日期及賣出標價、平台回收價或成交價。搜尋摘要可能保留舊價，優先採當下明細。賣場若只寫「亞服」或「各區另詢」，標明適用範圍尚未確認。可查 [U4N 永恆金幣列表第 2 頁](https://www.u4n.com/tw/world-of-warcraft-forever/gold?page=2)及 [8591 永恆遊戲幣](https://www.8591.com.tw/v3/mall/list/71641?searchType=0)。

- 外幣賣價乘以[台銀當日即期賣出匯率](https://www.bot.com.tw/tw/personal-banking/foreign-exchange)，換算成 `NT$/G`，另列 `NT$100 可換多少 G`。換算未含的費用另註。8591 使用 T 時按原報價單位標示。
- 2026-11-25 查證範例。U4N 明細顯示台服 PvP 部落 `US$0.264973/G`，以 `NT$33.065/USD` 換算約 `NT$8.76/G`，即 `NT$100 ≈ 11.4G`。8591 另有亞服宣傳 `10G＝35 T`，頁面寫各區比值另詢。兩筆皆屬當日查到的賣方掛價。 [U4N 報價明細](https://www.u4n.com/tw/world-of-warcraft-forever/gold/504054948544144) · [8591 亞服標價](https://www.8591.com.tw/v3/mall/detail/2420649801)
- 11/26 同一筆 U4N 賣單報 `US$0.206999/G`，以 `NT$33.005/USD` 換算約 `NT$6.83/G`，較前一日低約 22%。同一期間部落瑟銀錠的 20 件均價中位數從 22.75 銀升到 28 銀。用 `材料 G × NT$/G` 算台幣等值，用材料的 G 價算現有遊戲金幣的購買力。兩天的單一賣方報價只足以比較這筆報價的變動。 [台銀牌告匯率](https://rate.bot.com.tw/xrt) · [部落逐小時掛單](https://github.com/jakeuj/wow-forever-professions/tree/auction-data/hourly)

## 跨陣營價差

問「部落比聯盟便宜的有哪些」「哪些東西搬去中立賣有賺」時，在 repo 根目錄跑：

```sh
python3 '<skill-dir>/scripts/faction_spread.py'                # 前 30 名
python3 '<skill-dir>/scripts/faction_spread.py' --json > <暫存>/spread.json
```

- **做法**：部落價向官方 API 取一次即時掛單（要 Blizzard 憑證）；聯盟與中立價只有阿莫比物品頁有，所以先篩再讀頁：阿莫比全服中位數明顯高於部落最低價的前 `--cap`（300）項，加上部落 `--min-horde`（5g）以上的全部掛單，約 600 頁。快取到阿莫比下一次全掃描，同一輪重跑不會再抓；一天跑一兩次就好。部落 5g 以下、掛單多半在部落的便宜物品可能漏掉。
- **價差**＝聯盟最低一口價 − 部落最低一口價。部落玩家只能經中立拍賣場賣給聯盟，「轉賣淨利」用聯盟價與中立價較低者賣、扣 `--cut`（經典版 15%，沒算押金）；永恆的中立抽成還沒在遊戲內確認。
- **新舊**：各陣營價都附阿莫比「看到」的時間。多數物品共有的時間就是那間拍賣場最近一次全掃描（2026-11-23 時聯盟 01:11、中立 11/22 18:45）；比它舊的價格那次沒看到，可能已賣掉。舊的聯盟價另外列出，舊的中立價只顯示、不壓低轉賣淨利（例：克羅之刃中立 300g 是 11/18 的掛單）。
- **回答**：先講轉賣淨利為正的幾項，再給價差排名；寫明部落即時時間與聯盟掃描時間，提醒多數只有一兩件、聯盟那張可能是喊價過高。整份排名要放上網站時，見[網站維護](profession-planner-site.md)的跨陣營價差頁。

## 遊戲內資料與阿莫比對照

自家陣營價有三種比阿莫比新的來源：官方拍賣 API 的每小時資料（整間部落拍賣場，含材料與藥水）、拍賣小幫手的完整掃描（站主掃描的當下，聯盟或中立也能掃），以及拍賣場「收藏」清單的截圖。

### 拍賣小幫手（Auctionator）完整掃描

站主在拍賣場按「完整掃描」到 100% 後，請他輸入 `/reload` 或登出；插件只在這時把資料寫進 `_forever_/WTF/Account/<帳號>/SavedVariables/Auctionator.lua`，遊戲還開著時檔案可能不存在或還是舊的。接著跑：

```sh
python3 '<skill-dir>/scripts/auctionator_prices.py' --from-html speculation/index.html alchemy/index.html endgame/index.html
```

腳本只讀不寫，會解開壓縮資料並用阿莫比的物品清單補中文名稱；`--all` 列出整份掃描，`--json` 給後續計算，`--root` 指定其他安裝位置。輸出不含帳號與角色名稱，回報與頁面也不要寫進去。判讀時注意（插件 347 版實測，2026-11-18）：

- 資料庫依伺服器規則分組（亞服 PvP 是 `PvP`），**不分陣營拍賣場**；主城掃描的是部落拍賣場，在中立拍賣場掃描會混進同一份。請站主固定在主城掃，或說明在哪裡掃的。
- 每件物品只有最近一次最低價 `m`、每日最低與最高的低價 `l`／`h`，和當天看到的最多件數 `a`；日期從 2020-01-01 起算，物品本身不記時間；同一天掃兩次時，`m` 留的是最後看到的價格，看不出下午是不是已經賣掉，不能堆疊的物品改用官方每小時資料判斷現在有沒有貨。整份掃描的時間在 `AUCTIONATOR_SAVEDVARS` 的 `TimeOfLastReplicateScan`（舊版拍賣場是 `TimeOfLastGetAllScan`），是**開始**完整掃描的 Unix 秒，腳本會一併顯示；之後在拍賣場搜尋過的物品也會更新價格，直到存檔。
- 掃描裡沒有的物品，是掃描時那間拍賣場沒有掛單。
- 檔案中目前伺服器的資料是 CBOR 壓縮字串，字串欄位是位元組字串；版面改變時腳本會報錯，再對照插件 `Source/Variables/Main.lua` 與 `Source/Database/Mixin.lua` 修正。
- 插件「購物」分頁的「匯出結果」只匯出當次搜尋結果的 CSV，不含整個資料庫。
- 個人網站的[部落拍賣行情頁](https://jakeuj.com/wow-forever-professions/market/)由同一份存檔產生，重建方式見 [profession-planner-site.md](profession-planner-site.md)；站主掃描後要更新網站時，同時重建它。
- **購物清單匯入**：「購買」分頁左下「匯入」接受一行一份清單的 `清單名稱^"物品名稱"^"物品名稱"`；整個詞用雙引號包起來是完全比對，不加引號是包含比對（套裝前綴用）。要帶購買數量時，每個詞改寫成拍賣小幫手的進階搜尋字串：以 `;` 分成 14 欄，依序是搜尋詞、分類、最低／最高物品等級、最低／最高需求等級、最低／最高製作等級、最低／最高價（金）、品質、階級（空的寫 `#`）、資料片、數量，例如 `我的路線-鍛造225^"堅固的石頭";;;;;;;;;;;#;;167`。依據是插件的 `Source/Search/Advanced.lua`（`SplitAdvancedSearch`／`ReconstituteAdvancedSearch`），無限副本手冊的 `AuctionatorBridge.lua` 也這樣帶缺口數量（2026-11-23 本機核對）。`scripts/auction_brief.py` 的路線段會直接印出這種匯入行。同名清單會整份取代，其他清單不受影響。搜尋清單不需要物品有掛單，所以遊戲內收藏加不進去的沒貨配方可以用它盯。臨時要給清單時照這個格式輸出，放進 `text` 程式碼區塊方便複製；個人頁的清單由頁面標記產生，見 [profession-planner-site.md](profession-planner-site.md)；行情頁收藏的物品匯出成「行情-收藏」，插件「匯出」的同格式文字也能貼回行情頁加入收藏。

### 官方拍賣 API 每小時資料

repo 的排程每小時把亞服 PvP 部落拍賣場（TW 區 113 號）的最低一口價寫進 `auction-data` 分支的 `auctions.json`，排程維護見 [profession-planner-site.md](profession-planner-site.md)。2026-11-19 起同時收單件掛單與 `/commodities`，材料、藥水、食物、彈藥也在其中（見 [battlenet-api.md](battlenet-api.md#拍賣場)）；更早的快照只有裝備、武器、配方、容器這類不能堆疊的物品，所以材料的 24 小時漲跌與走勢要從那天之後才有。

```sh
curl -s https://raw.githubusercontent.com/jakeuj/wow-forever-professions/auction-data/auctions.json
```

- `updatedAt` 是最新快照的時間。`items[物品 ID]` 是 `[目前件數, [[時, 價], ...]]`，只記價格改變的時點：「時」是 UTC 的 Unix 時數（台灣時間加 8 小時），「價」是銅，`null` 表示從那時起沒貨，可能是賣掉也可能是到期。物品名稱與分類用 `market/data.json` 同一個 ID 對照。
- `hourlyFrom` 之後是逐小時資料，`hours` 列出實際收到的快照；更早的每天在台灣午夜留一個點，值是當天最低價，最多保留 90 天。格式以 `scripts/collect-auctions.py` 開頭的說明為準。
- 這是部落最新而且連續的價格，查部落裝備與配方的走勢、配方期貨買點時優先用它；對面陣營與中立拍賣場仍看阿莫比。
- 2026-11-23 前只靠 GitHub 的每小時排程，常延遲或漏跑（11/20 到下午只跑了 00、01、08 時；11/21～11/23 週末三天只收到 9 次），那段期間每天只有 3～4 個點。之後改由 Publisher Worker 每小時觸發兩次（見 [profession-planner-site.md](profession-planner-site.md)），仍先看 `updatedAt`。要現價和各價位件數（判斷「1g 的只有 1 張」）時，用下面的 `auction_changes.py --live` 取 API 與完整掃描較新的一份，不寫任何檔案。要把現價寫進自己的 `auctions.json` 複本時，用 `forever_api.py` 的 `credentials()` 取得憑證，設成 `BLIZZARD_CLIENT_ID`／`BLIZZARD_CLIENT_SECRET` 後跑 `python3 scripts/collect-auctions.py --out <暫存複本>`；不加 `--publish-depth` 就不影響網站。網站要跟著更新時改跑 `gh workflow run auction-collect.yml`。
- **期間漲跌**：站主幾天沒上線問「物價有什麼要注意」，或更新個人頁之前，跑：

  ```sh
  python3 '<skill-dir>/scripts/auction_changes.py' --from-html endgame/index.html alchemy/index.html speculation/index.html --since '2026-11-20 17' --live
  python3 '<skill-dir>/scripts/auction_changes.py' --movers --type 金屬 --min-price 0.05
  python3 '<skill-dir>/scripts/auction_changes.py' 秘銀錠 魔紋布 --ids 3859
  ```

  每項列出 `--since`（台灣時間，預設最新快照前 24 小時）當時的價、現在的價、漲跌、期間最低與最高和最近幾次變動；`--live` 再加上現價的各價位件數（API 與完整掃描取較新的）。`--movers` 改列全部物品的漲最多、跌最多、賣光與新上架，`--type` 依阿莫比的類型篩選（如 `金屬`、`草藥`、`藥水`、`鍊金術`）。名稱用阿莫比的物品清單對 ID，所以 `market/data.json` 沒掃到的配方與永恆新物品（如沉重瑟銀錠 251291）也查得到；同名時去掉垃圾品質（「黑蓮花」取草藥 13468，不取垃圾 6986）。
- **期間漲跌的判讀**：紀錄只有最低價、沒有各時點的件數，基準時點若只剩一張離群掛單，漲跌幅會失真（11/20 17 時卡德加的鬍鬚、地根草都是一張 50g，週一回到 3.50s、1.40s）。回報前用 `--live` 看現在各價位件數，並以站主的路線、庫存與個人頁物品為主，不必逐一列出全場漲跌。
- 阿莫比物品頁「各陣營拍賣場最近看到」的時間可能比官方快照新；部落價兩邊不同時，等下一次官方快照再寫進頁面。API 每小時更新一次，分鐘數會漂移（11/18 約 :06，11/20、11/23 約 :26），以回應的 `Last-Modified` 為準。

### 時段與星期的價格

站主問「幾點買材料比較便宜」「晚上貨比較多嗎」時用這段。`auctions.json` 只留最新件數，而且 2026-11-23 前每天只有 3～4 個快照，無法回答。當天用剩下的快照做過去趨勢檢查，沒有可靠的時段差：秘銀錠一天內在 10s～33s、瑟銀錠在 10s～36s 之間跳，但出現的時間不固定。從 2026-11-23 起，每小時把能堆疊物品寫進 `auction-data` 分支的 `hourly/<台灣日期>.jsonl`。每行是一個快照，每件物品記 `[最低單價, 上架件數, 最便宜 20 件均價]`，沒列出的物品就是沒貨。格式以 `scripts/collect-auctions.py` 開頭的說明為準。時段至少累積 7 天完整資料（每天 18 個快照以上）再看，星期至少三週。

```sh
python3 '<skill-dir>/scripts/auction_hours.py' 堅固的石頭 秘銀錠 鐵礦石 瑟銀錠 厚重的石頭 真銀錠
python3 '<skill-dir>/scripts/auction_hours.py' --category 金屬與石頭
python3 '<skill-dir>/scripts/auction_hours.py'             # 每個分類一行
python3 '<skill-dir>/scripts/auction_hours.py' 秘銀錠 --weekday
```

在 repo 根目錄執行，名稱與分類（`market/data.json` 的子類別，如 `金屬與石頭`、`草藥`、`布料`）才對得到。預設讀最近 28 天，3 小時一段（`--bucket 1～6`）。要反覆分析時，可用 `git worktree add <資料夾> origin/auction-data` 建本機複本，再加 `--source <資料夾>/hourly`。

- **方法**：每個時點都跟同一物品前後 12 小時的中位數比較（`--weekday` 用前後 3.5 天）。這個範圍正好包含一天的每個小時一次，可以扣掉好幾天的漲跌。如果直接拿各天的同一時段比較，一波漲勢會讓較晚的日子看起來比較貴。比值先在每天各時段平均，再取各天的中位數。分類會把各物品逐日平均，所以每一天只算一票。
- **判讀**：每格寫「比平常的百分比」和「n 天中幾天較低」，`*` 表示差 2% 以上，而且各天方向一致（雙尾符號檢定 p<0.05）。回答以「前20件均價」為準，因為它較接近站主一次買幾十個的成本；「最低價」常是一張離群掛單。沒有 `*` 就說沒有穩定的便宜時段，照觸發價買就好。有 `*` 的時段才建議等，並寫出差幾 % 與天數。「件數」看哪個時段貨多（例如晚上大家上線後掛單）。貨多不一定比較便宜，兩欄分開說。
- 結果只代表部落 113 號拍賣場和這段期間。改版、新副本或節日會改變行為，所以每隔幾週重跑，不要把一次的結論寫死在頁面上。

### 行情快訊：現在該買賣什麼

站主上班時問「拍賣場現在有什麼要處理」「有什麼該買或該賣」，只想看幾項要馬上動手的。先跑：

```sh
python3 '<skill-dir>/scripts/auction_brief.py'
```

在 repo 根目錄執行（或加 `--repo`）。腳本讀鍛造清單、煉金清單、配方期貨三頁的所有 `data-ah` 物品，取較新的部落現價（見[現價用哪個來源](#現價用哪個來源)），再拿 `auctions.json` 的 7 天紀錄和阿莫比的全服中位數當行情，有 Syndicator 存檔時也讀背包。

- **現在處理**（預設最多 5 項，`--max-now` 調整）：到了頁面的觸發價（`data-ah-buy-below`），而且那個價位以下只剩 3 件以內；沒有觸發價的頁面物品，價格在行情的四分之一以下也算。背包裡已經有的不推薦買，改列在「可以等」的「到價但你已經有」。背包裡的東西掛價到 7 天常見價 1.5 倍以上、總值 5g 以上、又沒超過行情 3 倍時列為「賣」，並寫出在哪個角色的背包、銀行或信箱。
- **可以等**：到價但貨還多、離觸發價 30% 以內、有觸發價但沒貨、可以試賣（總值不到 5g，或掛價超過行情 3 倍、不一定賣得掉；超過 3 倍又不到 5g 的不列），以及頁面外遠低於行情的配方（`--top` 筆）。
- **背包**：讀 Syndicator 存檔（`scripts/syndicator_inventory.py` 同一份，站主 `/reload` 或登出才更新），合計存檔所含角色的背包、銀行和信箱。缺少存檔時，快訊會註明庫存未扣除。買到的東西還在信箱時，回答最後提醒去領（見 [Syndicator](syndicator-inventory.md)）。
- **練等路線**：家目錄有 `.config/wow-forever/route.json` 時（格式見 [route.example.json](route.example.json)，每台電腦一份、不提交），「現在處理」之後多一段路線：要買的材料照即時掛單算買足的總價並對照路線估價；有商人價的（如煤塊 5s）比較拍賣場便宜的件數，省不到 1g 就直接叫站主找商人；中間材料（鋼錠＝鐵礦石＋煤塊、堅固的砂輪＝4 堅固的石頭）比較直接買和自己做，自己有的原料以拍賣價計；手上的材料對照 7 天常見價，低 15% 以上說先別賣、高 30% 以上說用不到的可以賣；列出的礦石比錠貴時提醒挖到的礦直接賣。`buy` 的 `qty` 是路線總需求；有背包存檔時腳本扣掉已有的，`hold` 的數量也改用存檔，所以只要換路線或練完一段才需要改 `route.json`，改法是 `leveling_route.py --me --to <下一個上限> --save-route`（見 [練等路線與成本](leveling-route.md#練等路線與成本)）；沒有存檔的電腦才手動改 `hold` 與 `updated`。
- 行情取阿莫比今天與前一天的全服中位數、部落 7 天常見價三者最低的那個，一張天價掛單不會讓東西看起來很便宜（11/23 漂亮的綠襯衣今天中位數 123.89g、前一天 7s）。奧金斧那種部落從沒掛過、聯盟 100g 的，仍會以阿莫比為準抓出來。

**回答格式**：開頭一行寫現價來源與時間，以及 API 下一次約幾點更新（API 每小時更新，分鐘數見[官方拍賣 API 每小時資料](#官方拍賣-api-每小時資料)）。接著「現在處理」逐項寫買或賣、物品、價格、還剩幾件和一句理由，最多五項；沒有就直接說沒有。有路線時接著放「你的練等路線」：每點先用粗體寫一句結論（照買、自己做比較省、先別賣、礦比錠貴），再補價格與件數，例如「**鋼錠在拍賣場跌到 10.59s，但還是自己熔比較省。**」。下面才放「可以等」，一行一類。要提醒的事（背包資料是上次登出時的、觸發價是頁面寫的）放最後一行。不要先貼整份漲跌表；站主要細節時再跑 `auction_changes.py`。腳本在每項後面標出是誰用的（依購物清單名稱：鐵匠→自己、煉金→煉金朋友、期貨→轉賣），回答照寫；「現在處理」全是煉金朋友的東西時，開頭先說明，並補一句鍛造本身有沒有要馬上買的（2026-11-23 那次三項都是朋友的轉化材料與配方）。

站主說已買到或快訊列出「到價但你已經有」時，從本次買入建議排除該項。站主要求同步個人採購頁與購物清單時，依[網站維護說明](profession-planner-site.md#個人整理頁終局採購清單)標記。已買到的東西進了背包、銀行或信箱，快訊讀存檔會自動排除，不必記；只有存檔看不到的（例：寄給還沒開信箱的小號）才在 local.md 的「存檔看不到的東西」記一筆，對方開信箱後刪掉。

大宗材料可設撿便宜通知，例如鐵匠清單的瑟銀錠 16s 是 11/19 起早期分布的約四分之一分位。到價且貨多時，快訊會列在「可以等」的「到價、貨還多」。要趕練等或有大宗缺口時，另用下節評估採買。

觸發價寫在頁面上：某項的建議改了（例如「10g 以下再看」改成 8g），`data-ah-buy-below` 要一起改，見 [profession-planner-site.md](profession-planner-site.md)。

### 大宗材料分批採買

1. **先算缺口與期限。** 用[依角色與庫存試算](leveling-route.md#依角色與庫存試算)重選路線，扣掉已用在前段的材料，再算衝到目標還缺多少。瑟銀礦石可在採礦 250 後以 1:1 熔成錠。把採礦尚未到 250 與已能熔煉的成本分開估，核對圖紙、學習門檻和成品去處。
2. **比較近期有量的價格。** 用 `auction_changes.py 瑟銀錠 瑟銀礦石 --live` 查最新價階，用 `auction-data` 的 `hourly/<台灣日期>.jsonl` 比最近幾天。取各日最便宜 20 件均價的中位數，只納入至少有 20 件的快照，標明有效快照數及是否為半天。每小時紀錄顯示的是掛單，用當下價階另算買足的總價並標明缺貨件數。
3. **列出回落、持平、上漲的預算。** 固定其餘材料或交代一併變動的假設，報買料與圖紙的總支出、賣店後淨花費，以及能否用當前金幣分段周轉。當持平或上漲仍能完成時，依期限決定先買幾成、首批均價上限和剩下的缺口。若下一段前沒有用料壓力，先練、採集或留現金。把[現金與遊戲金幣比值](#現金與遊戲金幣比值)用在台幣等值，材料的金幣預算依部落實際掛單與供需估算。

2026-11-26 部落範例。11/24、11/25、11/26 上午瑟銀錠的 20 件均價中位數依序為 18.10、22.75、28.00 銀（24、20、11 次有效快照）。11/26 上午仍有數小時回到 19～20 銀。12:19 掃描有 134 個瑟銀礦石掛在 20.68 銀，另有 161 個掛在 20.69 銀。有約 400 錠的確定缺口、之後可自行熔煉時，以 21 銀為上限先買 100 礦可把首批支出控制在 21g。若後續降到 16 銀，這一批相較直接等多花 4.68g。若漲到 26 銀，先買省 5.32g。每次依新價階、庫存和練等期限重算。 [部落逐小時掛單](https://github.com/jakeuj/wow-forever-professions/tree/auction-data/hourly)

### 收藏清單截圖

價格欄是單件最低一口價（金・銀・銅），「可用」是掛單件數，灰字「沒有可購買物品」是這間拍賣場目前沒貨。主城看到的是自家陣營拍賣場，中立拍賣場不在截圖裡。

### 對照步驟

1. 用 `amobi_item_prices.py` 查同樣的物品；更新個人頁時加 `--from-html` 一起查頁面上的所有物品。
2. 遊戲內資料或官方每小時資料晚於阿莫比最近一次全掃描時，自家陣營價以較新的為準；阿莫比補上對面陣營與中立拍賣場的價格，截圖時還要補上截圖沒有的物品。
3. 阿莫比有、遊戲內沒有的掛單，是中間被買走或下架；阿莫比較低、遊戲內較高，是低價那張被買走，表示那個價位有人接手（2026-11-18 魔暴龍護腿圖樣早上 15.81g，稍晚最低剩 18.81g）。同一個零頭的價格突然變成好幾十倍，多半是被買走後重掛（附魔手套 - 強效敏捷 0.53g → 55.53g）。好價沒在收藏清單裡時，提醒站主加進去。
4. 回報與頁面上標明每個價格來自遊戲內掃描、截圖還是阿莫比，以及日期與掃描時間。
