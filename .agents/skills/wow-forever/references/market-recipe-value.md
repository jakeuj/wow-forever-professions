# 拍賣行情與配方利潤

查證日期：2026-11-18（Asia/Taipei）。適用於「哪些配方值得從拍賣場買」「這項製造有沒有賺」「材料或成品現在多少錢」，以及依遊戲內拍賣場掃描或截圖更新價格。行情每天變動，結論一律以當次掃描重算；本檔只保存方法、資料格式與變動較慢的取得來源。

## 步驟

1. **確認伺服器與陣營。** 阿莫比按 ruleset 分開記價，目前有 `CAMWOW TW4 Realm 2 PvP`（亞服 PvP）、`CAMWOW TW4 Realm 1 PvE`、`CAMWOW US2 Realm 3 PvE`，以 [拍賣場物價](https://wowamobi.com/market) 的伺服器選單為準。提問者沒說時，依上下文推定（例如《黎明之劍》成員是亞服 PvP 部落），並在回覆寫明假設。
2. **跑腳本。**

   ```sh
   python3 '<skill-dir>/scripts/amobi_recipe_value.py' --profession alchemy --faction 部落 --sources
   ```

   `--profession` 用阿莫比的網址代號（alchemy、blacksmithing、enchanting、engineering、leatherworking、tailoring、cooking、first-aid）；附魔的成品是法術，只有配方價、沒有成品價。`--sources` 逐頁讀配方與材料的物品頁，取得分陣營最低價與 NPC 售價；煉金約 100 頁，首次約 3 分鐘，之後 6 小時內用快取（`--max-age` 調整）。`--all` 連本服沒有配方掛單的配方一起列；`--json` 輸出給後續計算。

   查指定物品，或個人頁上所有可複製的名稱時，改跑：

   ```sh
   python3 '<skill-dir>/scripts/amobi_item_prices.py' '配方：貓鼬藥劑' --from-html speculation/index.html alchemy/index.html endgame/index.html
   ```

   每項列出全服最低價、件數、日期與各拍賣場最近看到的最低價和時間；同名物品會標出品質與類型。快取預設 1 小時。
3. **逐列判讀**，先對照 [endgame-crafting.md](endgame-crafting.md) 的 60 級需求與永恆改動（沒涵蓋的專業先上網補查），再依下節規則把每個有掛單的配方歸入一類：**值得買**、**改向 NPC／任務取得**、**先別買**、**觀望**。歸類完成的條件：每項推薦都附上提問者陣營買得到的價格與張數，以及所需技能點。
4. **回報。** 先給分類結論，再註明伺服器／陣營假設、掃描時間，並說明價格是掛單價、不是成交價。

## 判讀規則

- **陣營價**：合併中位數混了聯盟、部落、中立三間拍賣場，便宜的那張常在對面陣營。推薦前看腳本的「{陣營}可買」（自家陣營與中立拍賣場的較低者）。分陣營價後面標了「（M/D 看到）」的，表示最近一次全掃描沒看到這筆，可能已經賣掉。物品頁的分陣營價屬於頁面標題的伺服器，與目標伺服器不同時腳本會略過並註明；只有一間拍賣場有掛單時，頁面不列分陣營區塊，腳本改從標題判斷是哪一方。
- **NPC 與任務優先**：腳本列出 NPC 售價時，AH 價高於 NPC 就改去 NPC 買；限量 NPC 常缺貨，小幅溢價可以接受。任務獎勵的配方也不必花錢，例如次級石盾藥水來自荒蕪之地任務「盧希恩的藥水」。
- **離群掛單**：只有 1～3 張時，中位數常被一張天價或一分錢拉偏（CraftProfit 改用「深度價」，取最便宜 20% 在售件數的平均價來避開，見[插件功能指南](addon-feature-guide.md#13-craftprofit-forever專業視窗內的配方利潤排序)；本 repo 的腳本目前仍用最低價）；要同時看最低價、張數，以及物品頁的每日走勢。近幾天才暴漲的配方先觀望，等價格回落。
- **毛利**：成品價 × 數量 × 0.95（拍賣場抽成）減材料；配方要做幾次才回本＝配方價 ÷ 每次毛利。材料用自家陣營買得到的價格，聯盟草藥常便宜好幾倍（2026-11-18 貓鼬藥劑的材料部落約 2.5g，每瓶只賺約 1.3g）。腳本同時用成品中位數與最低一口價各算一次，並依較低者排序；兩者差很多時以最低價為準，因為中位數可能被一批高價掛單撐高（例：2026-11-17 秘銀盾刺中位數 10 金，部落最低才 1.81 金）。材料按 AH 中位數計；不限量 NPC 的單價較低時改用 NPC，瓶子這類「一次 5 個」的組價，腳本已換算成單價。自己採的草藥仍有機會成本。
- **裝備類成品**：先到成品物品頁看綁定。拾取後綁定（例：黑鐵鎧甲）只有工匠本人能穿，配方價值看工匠的職業與用途。成品寫「需要鍛造（N）」的盾刺、武器鏈等永久附加物品，買家可能也得是鐵匠，轉賣行情要保守估。高階裝備的材料動輒數百金、又沒有成品掛單時，配方的價值在自用或公會開團，不在轉賣。
- **沒有成品掛單**：毛利空白代表沒有價格訊號，不代表不賺。永恆新增的藥劑多屬此類，依效果與團本需求判斷；配方便宜就先買起來卡位。
- **轉化**：有冷卻，毛利指每次冷卻的收益；冷卻長度以遊戲內配方說明為準。
- **礦石與錠**：熔煉一般是一礦一錠，礦石價卻可能高過錠（2026-11-23 部落秘銀礦石 25.74s、秘銀錠 19.99s；真銀礦石 53.99s、真銀錠 23.95s）。這時挖到的礦直接賣，要用錠就直接買錠；自己熔前先比兩邊價格。
- **技能**：配方可以先買，技能點夠了再學；回報時標出「需 N」。

## 配方期貨：囤配方等漲價

問「哪些配方可以先買起來等漲價」時，跨專業跑腳本（加 `--json`），挑出候選後再用 `--sources` 或物品頁看部落價、每日走勢與掉落來源；部落的每小時價格與上架件數看[官方拍賣 API 每小時資料](#官方拍賣-api-每小時資料)，哪個時段比較便宜看[時段與星期的價格](#時段與星期的價格)。經典版的價格史多半只有玩家留言，沒有可靠的長期序列（可信度：攻略與論壇），以下是歸納出的篩選條件：

1. **供給有上限**：只考慮稀有的怪物或首領掉落。商人有賣（含限量商人會補貨）、任務、訓練師、拾取綁定的配方不會漲；很多怪都會掉的配方，價格最後會落到地板價。永恆可能改來源，例：魔暴龍護腿圖樣在經典版是怪物掉落、後來的版本改由 Nergal 販售，永恆攻略寫護腿掉落、手套在 Nergal 賣。
2. **成品要人人反覆消耗**：精煉藥劑、團本藥劑、武器與裝備附魔、人人能穿的裝備。限職業、限專精或限鐵匠使用的成品，買家很少，流動性差。
3. **買在練功潮**：開服後幾個月，練功的人會把撿到的配方低價賣掉；物品頁每日走勢從高點跌到谷底、還有掛單時就是買點。最近一週已經漲了好幾倍的，買點已過。只剩個位數張數的低價可能一夜被掃光重掛（2026-11-17 晚間部落貓鼬藥劑 1.20g・3 張，11/18 變成 28.50g・11 張，聯盟同時 8.34g）：看到買點當下就買，被掃之後不追，手上有的分批賣。同一天也會發生：有限無敵藥水 11/18 上午 0.69g・5 張，下午被掃到 3g・3 張；強效敏捷手套公式那張 55.53g 的重掛消失後，17:06 出現 5g・1 張。所以頁面上每項都寫觸發價（如「10g 以下再買」），每小時資料一到價就提醒站主。
4. **賣在需求事件之前**：團本開放（永恆 2026-12-09）、需要抗性的團本、小號潮；開團當天的買家多半已經買好。經典版十字軍附魔公式開服初期最貴、之後一路下跌，所以「囤越久越漲」並不必然。
5. **每張少量、分批賣**：貴的配方賣得慢，官方也可能熱修來源（經典週年版曾當天修好限量配方被搶的問題、賽季服曾拿掉材料掉落）。
6. **跨陣營價差**：聯盟常比部落貴數倍；中立拍賣場兩邊都能買，可把部落低價買到的配方放到中立拍賣場賣。經典版中立拍賣場抽成 15%（陣營拍賣場 5%），永恆以遊戲內為準。

更新期貨頁的價格與分類：

1. 部落的配方與成品價格、件數用[官方拍賣 API 每小時資料](#官方拍賣-api-每小時資料)；官方資料裡沒有就是現在沒貨。官方資料比最新的完整掃描舊時改用掃描，聯盟與中立用 `amobi_item_prices.py --from-html speculation/index.html`。
2. 逐項對照頁面上的觸發價：到價的往 A 移，低價被掃光、漲回好幾倍的往 C 移，掛單一路變多、價格還在跌的寫「等止跌」。
3. 找新候選時，從官方資料挑出配方類（`market/data.json` 的類別 9）現價不到早上掃描一半的，再查跨陣營價與經典版來源。物品 ID 很大（25 萬以上）的是永恆新增物品，經典版經驗不適用，2026-11-18 看到的兩張（堅韌藥劑、徘徊者皮甲護手）在聯盟都不到 2g；來源說法不一的先不列，例如附魔武器 - 超強衝擊公式，經典版攻略說是黑石塔上層掉落，永恆資料站卻列為購買取得。

不適合囤的典型：秘銀馬刺、秘銀盾刺設計圖。經典版與永恆的成品都標「需要鍛造（215）」才能使用，非鐵匠要把物品放在交易視窗的「不會被交易」欄請鐵匠代裝，所以設計圖的買家幾乎只有接代裝生意的鐵匠；2026-11-17 部落 AH 還有 120 個秘銀馬刺成品、單價不到 1 金，設計圖一週內已經漲了數倍；秘銀盾刺設計圖 11/18 就從 9.50g 跌回 4g，掛單從 8 張變 11 張，中立拍賣場凌晨還有 0.66g。瑟銀盾刺設計圖在經典版非常稀有，是滿級副本坦克的首選盾刺，較有囤的條件。

## 遊戲內資料與阿莫比對照

自家陣營價有三種比阿莫比新的來源：官方拍賣 API 的每小時資料（整間部落拍賣場，含材料與藥水）、拍賣小幫手的完整掃描（站主掃描的當下，聯盟或中立也能掃），以及拍賣場「收藏」清單的截圖。

### 拍賣小幫手（Auctionator）完整掃描

站主在拍賣場按「完整掃描」到 100% 後，請他輸入 `/reload` 或登出；插件只在這時把資料寫進 `_forever_/WTF/Account/<帳號>/SavedVariables/Auctionator.lua`，遊戲還開著時檔案可能不存在或還是舊的。接著跑：

```sh
python3 '<skill-dir>/scripts/auctionator_prices.py' --from-html speculation/index.html alchemy/index.html endgame/index.html
```

腳本只讀不寫，會解開壓縮資料並用阿莫比的物品清單補中文名稱；`--all` 列出整份掃描，`--json` 給後續計算，`--root` 指定其他安裝位置。輸出不含帳號與角色名稱，回報與頁面也不要寫進去。判讀時注意（插件 347 版實測，2026-11-18）：

- 資料庫依伺服器規則分組（亞服 PvP 是 `PvP`），**不分陣營拍賣場**；主城掃描的是部落拍賣場，在中立拍賣場掃描會混進同一份。請站主固定在主城掃，或說明在哪裡掃的。
- 每件物品只有最近一次最低價 `m`、每日最低與最高的低價 `l`／`h`，和當天看到的最多件數 `a`；日期從 2020-01-01 起算，物品本身不記時間；同一天掃兩次時，`m` 留的是最後看到的價格，看不出下午是不是已經賣掉，不能堆疊的物品改用官方每小時資料判斷現在有沒有貨。整份掃描的時間在 `AUCTIONATOR_SAVEDVARS` 的 `TimeOfLastReplicateScan`（舊版拍賣場是 `TimeOfLastGetAllScan`），是**開始**完整掃描的 Unix 秒，腳本會一併顯示；之後在拍賣場搜尋過的物品也會更新價格，直到存檔。
- 掃描裡沒有的物品，是掃描時那間拍賣場沒有掛單。
- 檔案中目前伺服器的資料是 CBOR 壓縮字串，字串欄位是位元組字串；版面改變時腳本會報錯，再對照插件 `Source/Variables/Main.lua` 與 `Source/Database/Mixin.lua` 修正。
- 插件「購物」分頁的「匯出結果」只匯出當次搜尋結果的 CSV，不含整個資料庫。
- 個人網站的[部落拍賣行情頁](https://jakeuj.com/wow-forever-professions/market/)由同一份存檔產生，重建方式見 [profession-planner-site.md](profession-planner-site.md)；站主掃描後要更新網站時，同時重建它。
- **購物清單匯入**：「購買」分頁左下「匯入」接受一行一份清單的 `清單名稱^"物品名稱"^"物品名稱"`；整個詞用雙引號包起來是完全比對，不加引號是包含比對（套裝前綴用）。要帶購買數量時，每個詞改寫成拍賣小幫手的進階搜尋字串：以 `;` 分成 14 欄，依序是搜尋詞、分類、最低／最高物品等級、最低／最高需求等級、最低／最高製作等級、最低／最高價（金）、品質、階級（空的寫 `#`）、資料片、數量，例如 `我的路線-鍛造225^"堅固的石頭";;;;;;;;;;;#;;167`。依據是插件的 `Source/Search/Advanced.lua`（`SplitAdvancedSearch`／`ReconstituteAdvancedSearch`），無限副本手冊的 `AuctionatorBridge.lua` 也這樣帶缺口數量（2026-11-23 本機核對）。`scripts/auction_brief.py` 的路線段會直接印出這種匯入行。同名清單會整份取代，其他清單不受影響。搜尋清單不需要物品有掛單，所以遊戲內收藏加不進去的沒貨配方可以用它盯。臨時要給清單時照這個格式輸出，放進 `text` 程式碼區塊方便複製；個人頁的清單由頁面標記產生，見 [profession-planner-site.md](profession-planner-site.md)；行情頁收藏的物品匯出成「行情-收藏」，插件「匯出」的同格式文字也能貼回行情頁加入收藏。

### 官方拍賣 API 每小時資料

repo 的排程每小時把亞服 PvP 部落拍賣場（TW 區 113 號）的最低一口價寫進 `auction-data` 分支的 `auctions.json`，排程維護見 [profession-planner-site.md](profession-planner-site.md)。2026-11-19 起同時收單件掛單與 `/commodities`，材料、藥水、食物、彈藥也在其中（見 [battlenet-api.md](battlenet-api.md#拍賣場)）；更早的快照只有裝備、武器、配方、容器這類不能堆疊的物品，所以材料的 24 小時漲跌與走勢要從那天之後才有。

```sh
curl -s https://raw.githubusercontent.com/jakeuj/wow-forever-professions/auction-data/auctions.json
```

- `updatedAt` 是最新快照的時間。`items[物品 ID]` 是 `[目前件數, [[時, 價], ...]]`，只記價格改變的時點：「時」是 UTC 的 Unix 時數（台灣時間加 8 小時），「價」是銅，`null` 表示從那時起沒貨，可能是賣掉也可能是到期。物品名稱與分類用 `market/data.json` 同一個 ID 對照。
- `hourlyFrom` 之後是逐小時資料，`hours` 列出實際收到的快照；更早的每天在台灣午夜留一個點，值是當天最低價，最多保留 90 天。格式以 `scripts/collect-auctions.py` 開頭的說明為準。
- 這是部落最新而且連續的價格，查部落裝備與配方的走勢、配方期貨買點時優先用它；對面陣營與中立拍賣場仍看阿莫比。
- 2026-11-23 前只靠 GitHub 的每小時排程，常延遲或漏跑（11/20 到下午只跑了 00、01、08 時；11/21～11/23 週末三天只收到 9 次），那段期間每天只有 3～4 個點。之後改由 Publisher Worker 每小時觸發兩次（見 [profession-planner-site.md](profession-planner-site.md)），仍先看 `updatedAt`。要現價和各價位件數（判斷「1g 的只有 1 張」）時，用下面的 `auction_changes.py --live` 直接向 API 取一次，不寫任何檔案。要把現價寫進自己的 `auctions.json` 複本時，用 `forever_api.py` 的 `credentials()` 取得憑證，設成 `BLIZZARD_CLIENT_ID`／`BLIZZARD_CLIENT_SECRET` 後跑 `python3 scripts/collect-auctions.py --out <暫存複本>`；不加 `--publish-depth` 就不影響網站。網站要跟著更新時改跑 `gh workflow run auction-collect.yml`。
- **期間漲跌**：站主幾天沒上線問「物價有什麼要注意」，或更新個人頁之前，跑：

  ```sh
  python3 '<skill-dir>/scripts/auction_changes.py' --from-html endgame/index.html alchemy/index.html speculation/index.html --since '2026-11-20 17' --live
  python3 '<skill-dir>/scripts/auction_changes.py' --movers --type 金屬 --min-price 0.05
  python3 '<skill-dir>/scripts/auction_changes.py' 秘銀錠 魔紋布 --ids 3859
  ```

  每項列出 `--since`（台灣時間，預設最新快照前 24 小時）當時的價、現在的價、漲跌、期間最低與最高和最近幾次變動；`--live` 再加上 API 即時快照的各價位件數。`--movers` 改列全部物品的漲最多、跌最多、賣光與新上架，`--type` 依阿莫比的類型篩選（如 `金屬`、`草藥`、`藥水`、`鍊金術`）。名稱用阿莫比的物品清單對 ID，所以 `market/data.json` 沒掃到的配方與永恆新物品（如沉重瑟銀錠 251291）也查得到；同名時去掉垃圾品質（「黑蓮花」取草藥 13468，不取垃圾 6986）。
- **期間漲跌的判讀**：紀錄只有最低價、沒有各時點的件數，基準時點若只剩一張離群掛單，漲跌幅會失真（11/20 17 時卡德加的鬍鬚、地根草都是一張 50g，週一回到 3.50s、1.40s）。回報前用 `--live` 看現在各價位件數，並以站主的路線、庫存與個人頁物品為主，不必逐一列出全場漲跌。
- 阿莫比物品頁「各陣營拍賣場最近看到」的時間可能比官方快照新；部落價兩邊不同時，等下一次官方快照再寫進頁面。API 每小時更新一次，分鐘數會漂移（11/18 約 :06，11/20、11/23 約 :26），以回應的 `Last-Modified` 為準。

### 時段與星期的價格

站主問「幾點買材料比較便宜」「晚上貨比較多嗎」時用這段。`auctions.json` 只留最新件數，而且 2026-11-23 前每天只有 3～4 個快照，無法回答。當天用剩下的快照做過去趨勢檢查，沒有可靠的時段差：秘銀錠一天內在 10s～33s、瑟銀錠在 10s～36s 之間跳，但出現的時間不固定。從 2026-11-23 起，每小時把能堆疊物品寫進 `auction-data` 分支的 `hourly/<台灣日期>.jsonl`。每行是一個快照，每件物品記 `[最低單價, 上架件數, 最便宜 20 件均價]`，沒列出的物品就是沒貨。格式以 `scripts/collect-auctions.py` 開頭的說明為準。時段至少累積 7 天完整資料（每天 18 個快照以上）再看，星期至少三週。

```sh
python3 '<skill-dir>/scripts/auction_hours.py' 堅固的石頭 秘銀錠 鐵礦石 瑟銀錠 厚重的石頭 真銀錠
python3 '<skill-dir>/scripts/auction_hours.py' --category 金屬與石頭
python3 '<skill-dir>/scripts/auction_hours.py'             # 每個分類一行
python3 '<skill-dir>/scripts/auction_hours.py' 秘銀錠 --weekday
```

在 repo 根目錄執行，名稱與分類（`market/data.json` 的子類別，如 `金屬與石頭`、`草藥`、`布料`）才對得到。預設讀最近 28 天，3 小時一段（`--bucket 1～6`）。要反覆分析時，可用 `git worktree add <資料夾> origin/auction-data` 建本機複本，再加 `--source <資料夾>/hourly`。

- **方法**：每個時點都跟同一物品前後 12 小時的中位數比較（`--weekday` 用前後 3.5 天）。這個範圍正好包含一天的每個小時一次，可以扣掉好幾天的漲跌。如果直接拿各天的同一時段比較，一波漲勢會讓較晚的日子看起來比較貴。比值先在每天各時段平均，再取各天的中位數。分類會把各物品逐日平均，所以每一天只算一票。
- **判讀**：每格寫「比平常的百分比」和「n 天中幾天較低」，`*` 表示差 2% 以上，而且各天方向一致（雙尾符號檢定 p<0.05）。回答以「前20件均價」為準，因為它較接近站主一次買幾十個的成本；「最低價」常是一張離群掛單。沒有 `*` 就說沒有穩定的便宜時段，照觸發價買就好。有 `*` 的時段才建議等，並寫出差幾 % 與天數。「件數」看哪個時段貨多（例如晚上大家上線後掛單）。貨多不一定比較便宜，兩欄分開說。
- 結果只代表部落 113 號拍賣場和這段期間。改版、新副本或節日會改變行為，所以每隔幾週重跑，不要把一次的結論寫死在頁面上。

### 行情快訊：現在該買賣什麼

站主上班時問「拍賣場現在有什麼要處理」「有什麼該買或該賣」，只想看幾項要馬上動手的。先跑：

```sh
python3 '<skill-dir>/scripts/auction_brief.py'
```

在 repo 根目錄執行（或加 `--repo`）。腳本讀鍛造清單、煉金清單、配方期貨三頁的所有 `data-ah` 物品，向官方 API 取一次部落即時掛單，再拿 `auctions.json` 的 7 天紀錄和阿莫比的全服中位數當行情，有 Syndicator 存檔時也讀背包。

- **現在處理**（預設最多 5 項，`--max-now` 調整）：到了頁面的觸發價（`data-ah-buy-below`），而且那個價位以下只剩 3 件以內；沒有觸發價的頁面物品，價格在行情的四分之一以下也算。背包裡已經有的不推薦買，改列在「可以等」的「到價但你已經有」。背包裡的東西掛價到 7 天常見價 1.5 倍以上、總值 5g 以上、又沒超過行情 3 倍時列為「賣」，並寫出在哪個角色的背包、銀行或信箱。
- **可以等**：到價但貨還多、離觸發價 30% 以內、有觸發價但沒貨、可以試賣（總值不到 5g，或掛價超過行情 3 倍、不一定賣得掉；超過 3 倍又不到 5g 的不列），以及頁面外遠低於行情的配方（`--top` 筆）。
- **背包**：讀 Syndicator 存檔（`scripts/syndicator_inventory.py` 同一份，站主 `/reload` 或登出才更新），六個角色的背包、銀行、信箱合計。2026-11-23 第一次接上時，頁面上「再收」的配方有好幾張其實已在小號銀行；沒有存檔時快訊會註明沒扣掉已有的東西。買到的東西還在信箱時，回答最後提醒去領（見 [Syndicator](addon-feature-guide.md#syndicator讓-agent-讀得到背包)）。
- **練等路線**：家目錄有 `.config/wow-forever/route.json` 時（格式見 [route.example.json](route.example.json)，每台電腦一份、不提交），「現在處理」之後多一段路線：要買的材料照即時掛單算買足的總價並對照路線估價；有商人價的（如煤塊 5s）比較拍賣場便宜的件數，省不到 1g 就直接叫站主找商人；中間材料（鋼錠＝鐵礦石＋煤塊、堅固的砂輪＝4 堅固的石頭）比較直接買和自己做，自己有的原料以拍賣價計；手上的材料對照 7 天常見價，低 15% 以上說先別賣、高 30% 以上說用不到的可以賣；列出的礦石比錠貴時提醒挖到的礦直接賣。`buy` 的 `qty` 是路線總需求；有背包存檔時腳本扣掉已有的，`hold` 的數量也改用存檔，所以只要換路線或練完一段才需要改 `route.json`；沒有存檔的電腦才手動改 `hold` 與 `updated`。
- 行情取阿莫比今天與前一天的全服中位數、部落 7 天常見價三者最低的那個，一張天價掛單不會讓東西看起來很便宜（11/23 漂亮的綠襯衣今天中位數 123.89g、前一天 7s）。奧金斧那種部落從沒掛過、聯盟 100g 的，仍會以阿莫比為準抓出來。

**回答格式**：開頭一行寫即時快照時間，以及下一次約幾點更新（API 每小時更新，分鐘數見下方「官方拍賣 API 每小時資料」）。接著「現在處理」逐項寫買或賣、物品、價格、還剩幾件和一句理由，最多五項；沒有就直接說沒有。有路線時接著放「你的鍛造路線」：每點先用粗體寫一句結論（照買、自己做比較省、先別賣、礦比錠貴），再補價格與件數，例如「**鋼錠在拍賣場跌到 10.59s，但還是自己熔比較省。**」。下面才放「可以等」，一行一類。要提醒的事（背包資料是上次登出時的、觸發價是頁面寫的）放最後一行。不要先貼整份漲跌表；站主要細節時再跑 `auction_changes.py`。腳本在每項後面標出是誰用的（依購物清單名稱：鐵匠→自己、煉金→煉金朋友、期貨→轉賣），回答照寫；「現在處理」全是煉金朋友的東西時，開頭先說明，並補一句鍛造本身有沒有要馬上買的（2026-11-23 那次三項都是朋友的轉化材料與配方）。

站主說已經買到某項（或快訊列出「到價但你已經有」）時，這次回答先把它排除，再依 [profession-planner-site.md](profession-planner-site.md) 把頁面上那項改成已買到，並在 local.md 記一筆「已買到」，之後的建議才不會再推它。

大宗材料也可以設觸發價，例如鐵匠清單的瑟銀錠 16s（2026-11-23 依部落 11/19 起的價格分布，四分之一分位約 16s；鍛造 225→300 約要 970 個）。到價時通常還有很多件，快訊會列在「可以等」的「到價、貨還多」，回答時提醒分批買，不放進「現在處理」。

觸發價寫在頁面上：某項的建議改了（例如「10g 以下再看」改成 8g），`data-ah-buy-below` 要一起改，見 [profession-planner-site.md](profession-planner-site.md)。

### 收藏清單截圖

價格欄是單件最低一口價（金・銀・銅），「可用」是掛單件數，灰字「沒有可購買物品」是這間拍賣場目前沒貨。主城看到的是自家陣營拍賣場，中立拍賣場不在截圖裡。

### 對照步驟

1. 用 `amobi_item_prices.py` 查同樣的物品；更新個人頁時加 `--from-html` 一起查頁面上的所有物品。
2. 遊戲內資料或官方每小時資料晚於阿莫比最近一次全掃描時，自家陣營價以較新的為準；阿莫比補上對面陣營與中立拍賣場的價格，截圖時還要補上截圖沒有的物品。
3. 阿莫比有、遊戲內沒有的掛單，是中間被買走或下架；阿莫比較低、遊戲內較高，是低價那張被買走，表示那個價位有人接手（2026-11-18 魔暴龍護腿圖樣早上 15.81g，稍晚最低剩 18.81g）。同一個零頭的價格突然變成好幾十倍，多半是被買走後重掛（附魔手套 - 強效敏捷 0.53g → 55.53g）。好價沒在收藏清單裡時，提醒站主加進去。
4. 回報與頁面上標明每個價格來自遊戲內掃描、截圖還是阿莫比，以及日期與掃描時間。

## 練等路線與成本

問「從 N 練到 300 怎麼練最省、要準備多少錢」時，用部落掃描價排路線，不直接照抄攻略站的路線。玩家要在遊戲裡照自己的庫存與當下行情排，改用無限副本手冊（DungeonsForever）搭配拍賣小幫手，步驟見 [專業衝等操作](profession-addon-workflow.md)；兩邊總價差很多時，先查行情是否變動。

```sh
python3 '<skill-dir>/scripts/leveling_route.py' --profession blacksmithing --from 200 --to 300
```

**站主問「怎麼練」時先跑這兩個**（各約 10 秒）：

```sh
python3 '<skill-dir>/scripts/leveling_route.py' --me
python3 '<skill-dir>/scripts/leveling_route.py' --me --goal cash
```

第一個照市值排，已有的材料也算錢；第二個挑這次掏最少金幣、先用背包庫存的走法，最後列出比較過的幾條。

`--me` 從 local.md 讀主角色的 API slug，等於 `--character <slug> --live --bags`：
- `--character` 向 API 取目前技能、技能上限、角色等級、採礦技能與已學配方，所以 `--from`／`--to` 預設是目前技能到上限（2026-11-23：200→225）。路線跨過 225 這類門檻而角色等級不夠學下一階時，開頭印「注意」。
- 採礦技能夠的熔煉（鐵錠、鋼錠＝鐵錠＋煤塊、秘銀錠等，技能需求照經典版）算進自製來源，所以有礦的路線會比較「買錠」和「買礦自己熔」。
- `--live` 用官方 API 即時快照的最低價與件數，不必等完整掃描。
- `--bags` 讀 Syndicator：任何角色身上的設計圖不用再買（例：小號信箱裡的秘銀馬刺設計圖），材料表每項寫出已有的半成品抵掉多少、已有多少、還要買多少與現金，階段合計多一個「扣掉已有要花」。已有的材料仍以市價參與選配方，因為也可以拿去賣，所以不會為了用掉庫存而選貴的配方。
- **成品去處**：`--products vendor`（預設，賣商人）、`disenchant`（給附魔角色分解）、`keep`（保留，等於 `--no-vendor-sale`）。`--me` 讀 `route.json` 的 `"products"`，站主的路線是 `disenchant`。分解價值依物品品質、類別與物品等級，查 warcraft.wiki.gg 的經典版分解表（綠色護甲多出塵、武器多出精華，藍色出碎片；永恆未驗證），乘上部落價（今天最低價與 7 天常見價取較低者，因為附魔材料一天內就可能漲三倍）；不能分解的成品（馬刺、秘銀杆）改算賣店價。輸出每段寫「分解 Xg」或「賣店 Xg」。分解價值是材料能賣的掛單價，大量拿去賣會壓低價格，而且要賣掉才拿得到錢。
- **切換路線**：同樣的 `--me` 再加參數，就能比不同的走法（2026-11-23 13:26 即時價實測）：
  - `--products vendor`／`disenchant`／`keep`：成品賣商人、給附魔分解、保留。鍛造 200→225 分別跑出鋼質胸甲→秘銀鎧甲束褲→秘銀馬刺、重型秘銀手套→秘銀罩帽→秘銀細劍、秘銀杆→鋼質頭盔→秘銀馬刺。
  - `--use 鋼質頭盔,秘銀馬刺`：只用這些配方，算站主現在照走的路線要多少錢；`--avoid 秘銀細劍`：排除後看次好的。名稱用阿莫比的繁中配方名，打錯會直接列出對不到的名稱。
  - `--goal cash`（要 `--bags`，`--me` 已含）：已有的材料先用、不算錢，挑「這次掏最少金幣」的走法。比的是「材料＋設計圖與學費，扣掉賣店收回」，再加上用掉的已有材料買價的一成，避免為了省幾銅就把庫存燒光。逐點挑配方很短視：2026-11-23 第一版只走一次，先把已有的秘銀錠拿去做重型秘銀手套，後段只好買礦，算出 16.2g，比站主照走的頭盔＋馬刺還貴。現在把已有材料的權重設成買價的一成、五成、全額，每種再分「算／不算成品回收」各走一次；每條路線再逐一拿掉用到的配方重走，有省才拿掉（`prune_route`），最後取最省的。輸出最後的「比較過的走法」列出前四名的要花、用掉的已有材料與淨值，第一行是選用的。同日修正後實測：鋼質頭盔 200→210、秘銀馬刺 210→225，材料全在背包，只花學費 0.50g。讀結果時注意兩點：階段合計把已有的材料算 0，所以「材料」「淨」偏低（同例淨 −5.62g），照市值的淨成本看「比較過的走法」的「淨」；路線長短跟著庫存走，頭盔只做 10 次是因為背包剛好 140 根鋼錠，做到 212 就要再買煤和鐵礦，所以背包變了（`/reload` 後存檔才更新）要重跑。預設 `--goal value` 把已有的材料照市價算，因為也能賣掉。站主問「最省錢」時兩種都跑、並排比較，說明一個是少掏現金、一個是照市值的淨成本最低，不必先問他指哪一種。
- **學費與未學配方**：有 `--character` 時，還沒學的訓練師配方標「訓練師（未學，學費 Xg）」，學費取自網站配方庫，也算進選配方（省不了學費的配方會被換掉），階段合計另列學費。
- 沒算進去的：商人賣的配方以外的 NPC 限量。阿莫比對某些物品只列幾家商人，列到的不在主城時標「主城商人多半也有」。

2026-11-23 的教訓：只比賣店價時跑出鋼質胸甲、秘銀重斧，和站主「成品給附魔小號分解」的計畫不合；改算分解後先用了當天強效虛空精華 2.77g，罩帽、細劍看起來最划算；但前一天才 0.88g，改取 7 天常見價後，細劍每次淨約 0.64g，和馬刺的 0.69g 差不多，罩帽就不划算了。所以分解價值一定要防一天的漲價。分解表的物品等級要看物品等級，不是需求等級（秘銀罩帽需求 41、物品等級 46）。

回答時先給一句結論（照原路線、或哪一段換成什麼），再列各段配方與次數、「扣掉已有要花」的現金和要補買的材料。有 `route.json` 時，和它記的進行中路線比對：用 `--me --use <路線名稱裡的配方>` 算那條路線，和上面兩個結果並排成一張表（路線、還要花的現金、淨成本）；差別大才建議換，並說清楚省多少、要放棄什麼（例：罩帽可給附魔小號分解，馬刺不行）。背包材料多時，現金最省的那條通常就是把庫存用完的走法（2026-11-23：照市值的路線還要花 7.42g，現金最省 0.50g）。站主決定換路線後更新 `route.json` 和路線筆記。

- **資料**：配方、變黃／變綠／變灰點數、材料、NPC 售價與賣店價取自阿莫比 `/professions/{代號}` 與物品頁；價格與件數讀拍賣小幫手存檔（或 `--market-json market/data.json`）。阿莫比的訓練師配方沒寫學習技能，改用 `data/wowf-learn-skill-<代號>.json`（wowf.io 配方表的「技能等級」，`approx` 是網站標「~」的概估；目前只有鍛造）。要補其他專業時，在 wowf.io 的 `/tw/professions/<代號>` 配方表改成每頁 50 筆、逐頁讀名稱與技能等級，照同格式存檔並寫明擷取日期。
- **算法**：從低到高逐點挑「（材料 − 賣店價）÷ 升級機率」最低的配方；變黃前機率 100%，黃到灰為（灰 − 技能）÷（灰 − 黃）。材料從還有掛單的最便宜來源買，買一件扣一件；部落掛單不夠時改向不限量 NPC 買，或用路線當時已學會的訓練師配方自製（例：225 學的緻密砂輪＝厚重的石頭×4，比拍賣場便宜），超出掛單的件數以 3 倍最低價（`SHORT_PENALTY`）計，讓路線能換配方就換，換了更貴才保留並標「缺 N 件」。每段另算「多備」：升級次數第 90 百分位減期望值。設計圖只有省下的錢比售價多才留下；限對面陣營的配方排除。中立拍賣場預設不算，因為件數少、要跑一趟（`--neutral` 才算）。
- **讀結果**：賣店價常收回四到六成的材料錢，例如瑟銀巨劍、輻光護腿，所以要看淨花費。「缺 N 件」表示換配方也更貴、需要量仍超過部落掛單；拍賣小幫手的件數是當天看到最多的件數（全部價位加總），掃完又搜尋過會變大。腳本另列部落目前買不到、至少便宜 3 點以上的設計圖，回報時建議加進購物清單盯著。
- **和無限副本手冊的差別**（2.1.112 原始碼，2026-11-18）：升級機率幾乎相同（它是黃 100%→50%、綠 50%→5%，下限 5%）。它開「考慮拍賣行的銷售數量」（2.1.114 設定頁已不顯示，預設關閉）時照理同樣按件數採購，單價改用完整掃描時全部掛單的加權平均（扣掉自己的掛單），比這裡的最低價保守；2.1.112 存下的掃描每樣物品都不完整，這兩項用不到；2.1.116 的掃描已完整，還多存了每個價位的件數（見 [專業衝等操作](profession-addon-workflow.md)）。它的資料另把黑檀剃刃、華麗瑟銀手斧、巨型瑟銀戰斧設計圖記成 NPC 瑪格努斯·霜鳴販售，阿莫比沒有，所以兩邊路線的後半段可能不同。拍賣小幫手存檔沒有各價位件數，這裡算不出越買越貴，大量材料（如上千個瑟銀錠）會低估。它還會扣背包銀行庫存、可選成品拍賣回收與多備材料，所以兩邊總價差距大時以遊戲內為準。
- **成品拿去分解時**：無限副本手冊只比材料費，不管成品能不能分解；這裡加 `--products disenchant`（`--me` 照 `route.json`）才會算分解價值。只有綠色以上的護甲、武器能分解；消耗品與材料不行，即使是綠色，例如秘銀杆、秘銀馬刺、緻密平衡石、奧金骷髏鑰匙。同價位換成能分解的成品，例如 205→225 改做秘銀罩帽（一路橘色），235 起改做秘銀細劍或秘銀重靴。只有緻密平衡石便宜到值得照做（2026-11-19 約 0.09g）。護甲主要分解出塵，武器主要出精華，物品等級每 5 級換一檔材料（warcraft.wiki.gg 通用表，永恆未驗證）。永恆分解不看附魔技能高低，低技能的附魔角色就能拆（見 [拆裝小號](professions-and-legacy.md#裁縫附魔放哪個職業)）。
- **傳承「加班」**：插件介面寫滿級（5）時專業技能提升機率提高 20%。這裡和網站的次數都沒算進去，帳號有點時實際次數會少一些。
- **門檻**：`--gate`（預設 225）把路線切成兩段；鍛造的工匠級（225 以上）攻略寫要角色 35 級，回報時提醒，以遊戲內為準。訓練師學費與大量收購的漲價沒有算進去。
- **更新頁面**：`--json` 的結果交給 repo 的 `scripts/build-leveling-page.py`，見 [profession-planner-site.md](profession-planner-site.md)。

## 阿莫比資料格式

可信度：本次實測。以下是阿莫比網站自己使用的端點，沒有公開文件。回答玩家問題時低頻讀取並註明來源；公開網站依 [public-data-sources.md](public-data-sources.md) 的規則，只連結頁面。版面改變時，腳本會以「no recipes parsed」或找不到伺服器結束，此時改用瀏覽器閱讀頁面，再修正解析規則。

| 位置 | 內容 |
| --- | --- |
| `/api/market/items` | `groups[]` 每個伺服器一組，`items` 每列為 `[物品 ID, 中位數, 最低一口價, 上架數, 日期, 前次中位數, 前次日期]`，單位是銅；三間拍賣場合成一列：件數加總、最低價取最低、中位數用件數較多的那邊。每組另有 `lastFull`、`lastAny`（Unix 秒）與 `latest`（日期）。`meta[ID]` 第 1 欄是繁中名稱，第 2 欄是品質（0 垃圾、1 普通、2 優秀），第 4 欄是類型（如 `鍊金術`）；名稱可能重複，例如「黑蓮花」有垃圾與草藥兩件，要看品質與類型 |
| `/professions/{代號}` | 伺服器端產生的 HTML，每個 `li.pf-r` 是一筆配方：成品、技能點顏色、學習方式與 `配方：…` 物品、材料 `×N`、效果與「永恆新增」標記 |
| `/items/{ID}` | 每日價格表、「各陣營拍賣場最近看到的最低一口價」（附看到的時間），以及「阿莫比玩家記到的來源」中的商人、限量、組數與售價；最近一次全掃描沒看到時，頁面會註明顯示的是哪次掃描的價格。「經典版參考：怎麼取得」是經典版的掉落資料 |
